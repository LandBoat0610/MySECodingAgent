# Coding Agent 开发工作流知识

本知识文档用于辅助开发型 Agent 完成代码任务。Agent 在处理开发任务时，应优先遵循以下流程。

## 通用开发流程

1. 理解用户目标，确认要修改或创建的文件。
2. 查看相关现有文件，优先沿用项目已有风格和目录结构。
3. 小范围修改代码，避免无关重构。
4. 为新增功能或修复补充有针对性的测试。
5. 运行最小必要测试，再根据风险运行更大范围测试。
6. 最终回答应说明修改内容、验证结果和剩余风险。

## 代码修改原则

- 不要在源码中硬编码 API Key、Token、密码或数据库凭据。
- 新增 Python 函数应添加类型标注。
- 新增前端状态或接口时，应同步检查 store、API 封装和组件展示。
- 修改共享工具函数时，应补充回归测试。
- 遇到错误时先读完整错误栈，不要只根据错误名称猜测。

## 文件创建规则

- Python 工具函数文件应命名清晰，例如 `calc_utils.py`、`file_utils.py`。
- 测试文件应使用 `test_*.py` 命名。
- 前端组件测试应放在 `src/__tests__/components/` 或项目已有测试目录中。
- 文档类知识应放在 `docs/` 或更明确的子目录中。

## 验证优先级

简单 Python 功能优先运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q --tb=short
```

前端修改优先运行：

```powershell
cd agent\frontend
npm run test
```

如果只改了局部测试，可以先运行对应测试文件，再运行全量测试。
